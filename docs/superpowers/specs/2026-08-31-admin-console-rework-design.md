# /admin 控制面改版设计

**日期**：2026-08-31
**范围**：`src/nexus/admin/` 的界面层与三个账号端点、一个总览端点
**不在范围**：数据面鉴权（租户 key 仍是全权凭据）、放权的运行时写入路径（结构上不存在，本次不动）

## 为什么改

现在的 `/admin` 有三处让它「像个演示而不像个后台」：

1. **界面说的是实现的语言。** `diff`、`override`、`cross_tenant_read`、`substitutable_to`、`nano-USD` 直接印在屏幕上。控制面的使用者是运营和管理者，不是读过 `registry/effective.py` 的人。一个要先读源码才能看懂的后台，实际使用中会退化成「找工程的人帮我点一下」。
2. **操作散在列表下方。** 想调额度要先在表里找到那一行，再滚到页底的表单里重新选一遍业务线。选错行和选错下拉是两个独立的错误来源，而它们都会写进生效策略。
3. **有两处用了浏览器原生 `prompt()` / `confirm()`。** 停用业务线的理由是用 `prompt()` 收的——这个字段会 NOT NULL 落库并出现在审计里，用一个不能校验、不能取消重填、不能给提示的原生弹窗收它，是「看起来能用」的典型。

## 决策

| 决策 | 选了什么 | 理由 |
|---|---|---|
| 菜单 | 6 项（总览 + 业务/密钥/权限管理 + 操作日志 + 账户管理） | 总览是唯一能一眼看到全局异常的地方，散进各页就等于没有 |
| 变更申请 | 拆进对应菜单，不设独立菜单 | 「操作在当前菜单内完成」；申请单本来就是某个业务动作的产物 |
| 术语 | 全面中文化 | 原始英文只留在「待落地配置」文本框里 |
| 金额 | 界面收发美元 | 后端 nano-USD 一行不改，前端换算 |
| 文件 | 拆成 4 个静态文件 | 单文件会到 1400 行；术语字典单独成表才可审阅 |
| 重置他人密码 | **不做** | 一个 rw 管理员能把另一个管理员的密码改成自己知道的值，再以对方身份登录——预算提额的二人复核假设会塌 |

## 信息架构

### 01 总览

一个真 dashboard，数据来自新增的 `GET /admin/overview`。

- **常驻运行状态条**：当前上游是真实供应商还是内置假上游。README 为 `/console` 立了这条规矩而 `/admin` 一直没有；管理员盯着假上游产生的花费做提额决策，正是这条规矩存在的原因。
- **今日统计卡**：今日调用次数与花费 / 额度水位与超额业务线数 / 业务线在线与停用 / 有效密钥数。
- **异常告警区**，九类，各带条数与跳转：超额业务线、额度为 0 的业务线、被否决的模型替换、发生过降级的调用、失败与中断占比、已失效的管控、未覆盖质量门禁的业务线、待发布的变更申请、被冻结或登录失败异常的账号。
- **今日用量分布**：按业务线花费、按模型调用次数，各 Top 5，纯 CSS 条，不引图表库。
- **最近 6 条操作**。

**两个口径，必须分别标注。** 账本推导的数字（用量、花费、超额、失败率）标「今日」，用的是网关判 429 时的同一个 `policy.quota.day_start`，不是朴素 24 小时——`/console/quota` 的 docstring 记着上一次把整本账当成一天的教训。路由否决与降级记录来自 `RoutingLog`，那是**进程内存**、每类上限 500 条、重启即失，所以标「本次启动以来」。两个口径都写成「今日」，会让一次重启看起来像异常消失了。

**三态诚实。** 0 条显示「无」，没有数据显示「暂无数据可判」，不画绿灯。把 `not_covered` 画成 pass 的面板比没有面板更危险，这条在门禁矩阵上已经付过学费。

### 02 业务管理

表格列：业务线 / 接入方式 / 状态 / 日额度 / 自动降级 / 有效密钥数。展开行显示跨业务线查账与可替代模型的**声明值与生效值并排**，被收回的划掉标黄。

行内操作（均为 dialog，业务线已预选）：调整日额度、停用业务线、恢复业务线、查看详情。
页头操作：新增业务线 → 出变更申请单。
页底：新增业务线的申请记录。

调额度 dialog 内实时计算并显示方向：「当前 $5.00 → 新值 $16.00，提额 3.2 倍，超过阈值，需要第二位管理员复核」。复核人是**下拉**，取活跃的可操作账号并排除自己——服务端本来就只接受已知管理员，自由文本框让人填完提交才知道错。

### 03 密钥管理

发放密钥的明文在 dialog 内展示，必须勾选「我已保存」才能关闭。吊销要求填理由并**手打密钥前缀确认**：吊销没有逆操作，一次误点就是一次业务中断。

### 04 权限管理

按业务线列三类权限现状，被收回的划掉标黄，顶部是「已失效的管控」告警。
行内操作：收回权限、撤销收回、申请放开权限。页底是放权申请记录与「查看待落地配置」。

**收回立即生效、放开只出申请**这条方向性约束不变，界面上用两块颜色区分，文案不再提 override 与 proposal。

### 05 操作日志

带操作人、业务线、动作类型三个筛选。动作名全部中文。点行打开详情 dialog，改动前后逐项中文对照。

### 06 账户管理

新增账号、停用、恢复、解冻，加上右上角「修改我的密码」。首个账号仍然只能从命令行创建，这条不动。

## 术语字典（`terms.js`）

界面上彻底消失的词：`diff` `override` `proposal` `tenant` `nano-USD` `G1/G4` `orphan` `rw/ro` `zero_touch`。

| 原词 | 界面用词 |
|---|---|
| diff / 提案 diff | 待落地配置 |
| proposal / 提案 | 变更申请单 |
| override / 覆盖 | 权限收回 |
| 孤儿覆盖 | 已失效的管控 |
| tenant | 业务线 |
| cross_tenant_read | 跨业务线查账 |
| substitutable_to | 可替代模型 |
| allow_fallback | 自动降级 |
| enabled | 启用状态 |
| budget_nanousd_per_day | 日额度 |
| zero_touch / native | 零侵入接入 / 原生接入 |
| gate_command | 质量门禁 |
| G1 / G4 | 多样性红线 / 降级透明红线 |
| clean / would_violate / no_evidence / not_applicable | 通过 / 会触碰红线 / 暂无数据可判 / 不适用 |
| rw / ro | 可操作 / 只读 |
| pending / shipped | 待发布 / 已生效 |
| active / revoked / locked / disabled | 有效 / 已吊销 / 已冻结 / 已停用 |
| 审计动作名（14 条） | 停用业务线 / 收回跨业务线查账 / 调整日额度 / 发放密钥 / … |

原始英文字段只存活在**「待落地配置」文本框**里。那段要交给工程侧落进 `policies/<tenant>.yaml`，翻译它等于交付一份跑不通的配置。

## dialog 引擎

原生 `<dialog>`，无依赖。三个入口：

- `openForm({title, intro, fields, submitLabel, danger, onSubmit})`，字段声明式：`{name, label, type: text|password|select|money|static|textarea, hint, required, options, value}`
- `confirmDialog({..., requireTyping})`
- `infoDialog()`

三条行为约束：

1. **服务端报错渲染在 dialog 内部**，不是一条会消失的 toast。用户填的值原样保留可改。一个把错误信息和输入内容同时清掉的表单，逼人从头再填一遍。
2. 提交中按钮转 in-flight，期间禁止 ESC 与点背景关闭。
3. 只读管理员的行按钮直接 `disabled` 并带 `title` 说明原因，而不是点开填完才被 403 拒绝。

## 后端改动

| 改动 | 说明 |
|---|---|
| `AccountStore.enable()` | 停用现在是单向门，连 CLI 都没有恢复 |
| `AccountStore.unlock()` | 登录失败锁定现在只能干等锁定期 |
| `POST /admin/password` | 改自己的密码，验旧密码，成功后撤销自己的其他会话 |
| `POST /admin/accounts/{u}/enable` | |
| `POST /admin/accounts/{u}/unlock` | |
| `GET /admin/overview` | 总览聚合。console 的五块面板用租户 key 鉴权并按 scope 裁剪，控制面会话调不了 |
| `diff` → `config` | 放权申请单响应的字段名，与术语要求直接冲突 |

三个账号写操作都记审计。

## 文件结构

```
src/nexus/admin/static/
  admin.html    页壳 + 登录卡 + 六个空视图容器
  admin.css     设计系统 + dialog 样式
  admin.js      数据 / 渲染 / dialog 引擎
  terms.js      术语字典
```

三个新增 `FileResponse` 路由，与页壳一样匿名可取——它们不含任何数据，这与现有 `admin_page()` 的 docstring 是同一条论证。

## 测试

- 三个新端点：改密码要验旧密码、改完旧会话失效、不能停用自己、恢复与解冻走审计
- `GET /admin/overview` 需要会话；无账本数据时返回「暂无数据可判」而不是 0 当成正常
- 四个静态文件都能取到且都不含数据
- **术语覆盖测试**：遍历 `api.py` 里所有 `cp.record(...)` 的动作名，断言 `terms.js` 里都有对应中文。以后加动作忘了加翻译，测试红，而不是日志里冒出一行 `override.add.foo`
